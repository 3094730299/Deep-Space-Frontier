> 2026-10-24 整理。

## 一、最重要的工作流

1. **先看 `docs/待办清单.md`**
   - 它是“还缺什么”的唯一出处；
   - 不要凭记忆列任务，容易漏。

2. **先 `git status`**
   - 这个仓库经常有一大批未提交改动；
   - 先分清哪些是已完成的、哪些是半成品；
   - 改新功能前，能提交就先提交一次保命。

3. **一次只做一个能编译的闭环**
   - 数据 → 服务端 → 网络 → 界面 → 资源 → 构建；
   - 不要同时改 8 个文件、最后一起编译；
   - 上下文快满时，尤其不要开大功能。

4. **每轮结束前**
   - `gradlew build`
   - `tools/validate.py`
   - `tools/verify_readme_claims.py`
   - `tools/check_gecko_textures.py`
   - `tools/install.py`
   - 更新 `publish/更新日志.md` 和 `docs/待办清单.md`

5. **构建成功 ≠ 实机可用**
   - `validate.py` 只查资源/注册/模型引用；
   - 点击坐标、主题叠层、库存/补货、物理结构必须实机看。

## 二、这个仓库的坑

### 1. Gradle 输出 exit code 1 不一定是失败

`gradlew.bat` 把 stderr 当 PowerShell 错误时，`Select-Object` 管道可能返回 exit code 1，但最后一行是：

```text
BUILD SUCCESSFUL
```

**看最后几行**，不要只看退出码。

### 2. PowerShell 中文编码

- `Get-Content` / 输出经常乱码；
- 写 Markdown/JSON 一律用 Python `encoding='utf-8'`；
- 不要用 PowerShell 直接 `Set-Content` 写中文文档。

### 3. 协议版本每次改包都要 +1

- `net/ModPayloads.java` 的 `VERSION`；
- 改 `ShopDataPayload` / `ShopRulesPayload` / `ModuleListPayload` 都要升；
- 旧客户端/服务端不兼容，实机必须同版本。

### 4. `StreamCodec.composite` 参数数量有限

- 5 个字段以内很稳；
- 到 7/8 个字段时容易报“找不到合适的方法”；
- 超过时直接用：

```java
StreamCodec.of(
    (buf, payload) -> {
        buf.writeUtf(...);
        buf.writeVarInt(...);
    },
    buf -> new Payload(...)
);
```

- `ByteBuf` 没有 `writeUtf/readUtf`，要用 `FriendlyByteBuf`。

### 5. 旧存档兼容

- 新字段先给默认值；
- 旧 NBT 缺字段不要崩；
- 方块状态属性（`company` / `tier`）不能随便删，旧世界会读；
- 机器 id 不要改，改了旧机器变空气。

### 6. 删除/重命名资源要查引用

- `validate.py` 会查模型/贴图/掉落/语言；
- 但不会查 Java 里的硬编码；
- 删旧变体前先 `grep` 整个仓库。

### 7. 别在上下文快满时开大功能

这次通用终端改造就是例子：

- 设计确认完了；
- 但上下文已经不够安全改 8 槽/双卡/库存/UI；
- 硬改容易出现“编译不过 + 没上下文修”的半成品。

**正确做法**：先提交当前改动，再开新会话，把交接清单带过去。

## 三、经济/商店相关的经验

### 1. 先把规则写成玩家能懂的一句话

反例：

> 等级影响价格倍率

玩家会问：到底几倍？为什么这家贵？

正例：

> 低级 1 组/1.5 秒，中级 2 组/1 秒，高级 3 组/0.5 秒；等级不影响价格。

规则要能直接贴到界面/README 里。

### 2. 库存不要只写数字

只写 `库存 2/3` 不够；要同时给：

- 上限；
- 本轮实际值；
- 下次补货倒计时；
- 售罄提示。

### 3. 波动规则要先定“每台独立还是全公司共享”

这次最终定的是：

- **每台商店独立**；
- 每家公司独立基准；
- 种类波动两个开关；
- 库存波动全局百分比。

如果一开始不定，后面会反复改数据结构和 UI。

### 4. 双卡支付先定“整笔优先还是拆笔”

这次定的是：

- 卡 1 够 → 整笔卡 1；
- 卡 1 不够 → 整笔卡 2；
- 都不够 → 失败；
- **不拆笔**。

拆笔会牵扯退款/找零/部分成交，复杂度高很多。

### 5. 收购机价格和速度分离

老板明确要“等级只影响速度”后：

- 删掉 `0.8/1.0/1.2` 价格倍率；
- 速度：低 1 组/1.5s、中 2 组/1s、高 3 组/0.5s；
- 一组 = 一个输入格那叠；
- 仍保留 64/tick、2000/tick 安全上限；
- 动画只做表现，不阻塞结算。

## 四、模块打印机的经验

- 模块打印机是**独立新机器**，不是 CORE 第二模式；
- 只读 `config/deepspacedeployer/modules/`，不读玩家 Sable；
- 载具打印机读玩家 Sable + `config/deepspacedeployer/vehicles/`；
- 模块只扣公司账户，不耗材料；
- 价格/等级/公司由 `.json` 预设；
- **仓库没有附带模块 `.nbt`**，所以列表默认空；
- 不要在没预设时以为机器坏了。

低級模型试做后老板觉得不好看，结论：

- 先当占位，不要急着把 6 公司 × 3 等级全接进去；
- 等老板自己建好模型，再一次性接；
- 模型文件放 `art/建模计划/模块打印机/`。

## 五、Blockbench / 建模经验

- 本机 Blockbench 5.2.2，GeckoLib 插件已装；
- 现有 `建模/` 里有收购机、通用终端等 `.bbmodel` / `.geo.json`；
- 可以直接写 `.bbmodel` JSON（Java Block/Item 格式），嵌入 base64 贴图；
- 用 BAE（Blockbench Agent Runtime）可以离屏渲染 `.bbmodel`：
  - 但它是 YSM 专用运行时，不是通用 Java 模型工具；
  - 它构建在 `C:\Users\30947\Tools\blockbench-ysm-agent`，不污染正常 Blockbench；
  - 正常 Blockbench 的安装目录没被改。
- 不要一上来接“隐藏窗口全自动建模”：
  - 第三方项目要 clone 上游、pnpm、Electron；
  - 构建/依赖/网络都重；
  - 先做文件级 `.bbmodel`，老板能打开看，最稳。
- 建模反馈要具体：
  - 太方、模块太大、灯带太抢、龙门看不见；
  - 这些比“不好看”更能指导下一版。

## 六、文档经验

- 每个方块单独 README 很有用；
- 旧的 `玩法手册.md` 容易过时（还写着 0.8/1.2 和 18 变体），新文档要明确写“按当前构建”；
- `docs/方块说明/` 是新增的准确版本；
- 交接清单要单独写，不要把关键状态埋在聊天里；
- 中文文件名可以，但链接要测。

## 七、AI/上下文经验

- 上下文快满时，**不要开始大功能**；
- 先把：
  - 当前改动提交；
  - 交接清单写到磁盘；
  - 新会话要读的文件列出来；
- 不要为了“显得在做事”硬改一半；
- 半成品比没开始更糟。

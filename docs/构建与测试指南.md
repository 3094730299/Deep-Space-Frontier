# 深空铸造体 · 构建与测试指南（给没有代码基础的你）

> 这一页只讲「怎么把它变成能玩的模组」。改数值/改价格不用看这里，看数据包文档。

---

## 0. 你现在手里有什么

```
deep-space-deployer\                ← 整个模组工程
├── build.gradle                   构建脚本（一般不用动）
├── gradle.properties              版本号在这里改（NeoForge / MC 版本）
├── src\main\java\...\             代码
├── src\main\resources\            贴图、模型、语言文件、数据包
├── tools\gen_textures.py          一键重新生成贴图与模型
├── tools\preview.py               把贴图放大拼成一张预览图
└── docs\                          说明文档（就是这一页）
```

**构建产物**：`build\libs\deepspacedeployer-0.1.20+mc1.21.1.jar` ← 这个文件就是模组本体。

## 1. 用命令行构建（最简单）

在工程文件夹里打开 PowerShell：

```powershell
cd C:\Users\30947\Documents\deepseek-harness\default-workspace\deep-space-deployer
.\gradlew.bat build
```

第一次会下载几百 MB 的依赖（NeoForge + Minecraft），要等几分钟。
成功的话最后会看到 `BUILD SUCCESSFUL`，产物在 `build\libs\`。

> ⚠️ 国内网络注意：官方 `maven.neoforged.net` 在你这台机器上**被 DNS 污染**（解析到 Facebook 的 IP），
> 每次访问都要等到超时。工程里已经做了两层修正，正常情况下你不用管：
> 1. `build.gradle` 里把 NeoForge 官方 CDN 镜像 `neoforged.forgecdn.net` 放在第一位，
>    并且会把 ModDevGradle 自己添加的 `maven.neoforged.net` 仓库**自动改写**成这个镜像；
> 2. `gradle.properties` 里把 Minecraft 版本清单指向官方 `piston-meta.mojang.com`。
>
> 如果哪天镜像也挂了，报错会明确写出"找不到 xxx"，把报错发我即可。

## 2. 用 IDEA 构建（改代码方便）

1. 装 **IntelliJ IDEA Community**（免费版就够）

## 4. 进游戏后的第一件事：跑自检

装好模组启动游戏后，**先跑这一条**（需要 OP）：

```
/dsd selftest
```

它会一次性打印：模组版本、4 个方块和 7 个物品的注册情况、**六家公司价目表里有没有写错的物品 id**、
蓝图文件夹读到几份（含尺寸和材料数）、所有配置值、声望存档能否读写、联动探测报告、
以及**世界生成注册情况（18 结构 / 3 结构集）**。
输出同时会写进 `logs\latest.log`（搜 `[自检]`），**把这一段整段发我就能定位大部分问题**。

相关指令：

| 指令 | 作用 |
|---|---|
| `/dsd selftest` | 全套自检（上面那个） |
| `/dsd integration` | 只看联动探测（哪些模组装了、能调到哪些方法） |
| `/dsd reloadblueprints` | 改完蓝图文件夹后重新读取 |

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Could not resolve net.neoforged:neoforge` | 网络问题，确认 `build.gradle` 里的仓库改写代码还在（别删那段"国内网络修正"） |
| 构建卡在 `:createMinecraftArtifacts` 十几分钟没动静 | 基本就是被墙了：确认 `gradle.properties` 里的 `launcherManifestUrl` 指向 piston-meta |
| 游戏里找不到模组 | 检查 jar 是否放进 `versions\孢子危机\mods\`；检查是不是 1.21.1 + NeoForge |
| 界面一片黑 / 按钮错位 | 把游戏界面缩放调到 2 或 3 再试；截图发我 |
| 方块放下去是紫黑格 | 贴图没打包进去，重新 `python tools\gen_textures.py` 再构建（手绘的三张物品贴图不会被覆盖） |
| 启动崩溃 `Missing or unsupported mandatory dependencies` | mods.toml 里写死了 create 依赖；如果你连机械动力都没装就会这样 |

## 5. 以后每次改完代码

```powershell
.\gradlew.bat build        # 只构建
.\gradlew.bat runClient    # 直接开游戏测试（开发环境）
```

改**贴图/颜色**：先改 `tools\gen_textures.py` 里的配色表，再跑
`python tools\gen_textures.py` 和 `python tools\preview.py`，然后构建。

> ⚠️ **有三张物品贴图是手绘定稿，生成脚本不会覆盖它们**：
> `bank_card.png`（银行卡）、`blueprint_voucher.png`（蓝图凭证）、`tier_upgrade_kit.png`（等级升级套件）。
> 定稿原图备份在 `art\手绘定稿\`，程序生成的旧版备份在 `art\程序生成-备份\`。
> 想换这几张：直接把新 PNG（16×16）覆盖到
> `src\main\resources\assets\deepspacedeployer\textures\item\` 下同名文件，再构建即可。

改**版本号 / 模组名**：只改 `gradle.properties`（别改 `build.gradle` 里的替换逻辑）。

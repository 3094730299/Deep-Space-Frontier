# 深空铸造体 · 自定义界面主题开发文档

> **这份文档是给"要自己写一套界面"的人看的**（玩家、老板、接手的 AI 都算）。
> 看完你应该能：从零做出一套主题、知道每种写法能不能用、不用开游戏就验证对错。
>
> 最后更新：2026-10-18 · 对应模组 **0.1.6+mc1.21.1** · 主题版本 **2.1.0**

---

## 零、先看这段：这套东西是什么

游戏里所有**方块界面**（商店、收购机、载具打印机、寄售市场、资金转化、选投放点、银行卡绑定、
通用终端、价目表编辑器）和**主题选择菜单**，外观都可以由玩家用 **HTML + CSS** 自己写。

内置的渲染器叫 **WebView**（`com.deepspacedeployer.ui.webview` 包）—— 名字借用了"网页视图"的叫法，
因为写法和网页一样（`.html` + `.css` + 相对路径引用图片），但**它不是浏览器内核**。

### 为什么不用真正的浏览器内核（重要，别再纠结这件事）

| 方案 | 实测代价 | 能不能满足"模组内置、玩家零安装" |
|---|---|---|
| **Chromium（MCEF / JCEF）** | Chromium 原生库要**运行期下载**（上百 MB），而且要玩家**先装另一个模组** | ❌ 不满足 |
| **JavaFX WebView** | `javafx-web` 实测 **Win 30.5 MB + Linux 39.0 MB + macOS 31.6 MB + macOS-arm64 29.7 MB = 131 MB**，加 `javafx-graphics`/`javafx-base` 共约 **148 MB**（当前模组 jar 只有 0.8 MB） | ⚠️ 要拆成三个操作系统各一个发布包（CurseForge 单文件上限 100 MB，一个包塞不下）；缺原生库时不是"报错"而是**加载类直接崩 JVM** |
| **自己写 HTML/CSS 子集渲染器**（现在这个） | **约 100 KB 纯 Java**，无原生库、无平台差异 | ✅ 单包、任何系统一样、还能**离线出图验证** |

**一个决定性的区别**：自写渲染器**能在这台机器上验证**（离线编译 + 出 PNG，见第五节），
JavaFX 方案只有真启动游戏才知道行不行，而且只能验当前这一个操作系统 ——
对"改一次就要老板实机确认一次"的项目来说，这个差别比渲染还原度重要得多。

> 将来真要上 JavaFX：`WebViewScreen` 那层接口是隔离的，换掉渲染层即可，**主题文件一个字都不用改**。

## 一、目录约定（老板定稿）

```
<版本文件夹>/deepspacedeployer/theme/          ← 例如 .minecraft/versions/孢子危机/deepspacedeployer/theme/
├── default/                                   ← 模组内置的默认主题（首次启动自动释放到磁盘）
│   │                                             ⚠️ 模组更新时会被整份覆盖，改这里等于白改
│   ├── index.json                             元数据：名称 / 作者 / 版本 / 介绍
│   ├── version.txt                            版本标记（和 jar 里不一致就重写 default/）
│   ├── theme.css                              公共样式（十个界面共用）
│   ├── factory_terminal.html                  工厂终端（商店）
│   ├── buyer.html                             收购投送机
│   ├── factory_core.html                      载具打印机
│   ├── market.html                            寄售市场
│   ├── transfer.html                          资金转化
│   ├── assembly_map.html                      投放点选择（俯视图点地图）
│   ├── card_bind.html                         银行卡绑定
│   ├── universal_terminal.html                通用终端
│   ├── shop_editor.html                       价目表编辑器（OP）
│   └── choice.html                            旧的主题选择菜单（游戏内已不加载，预览用）
└── custom/
    └── AUI/                                    ← 一套自定义主题 = 一个文件夹
        ├── index.json                         元数据（可选，主题菜单里显示名称/作者）
        ├── theme.css                          只放这一个文件 → 十个界面都换成你的配色
        ├── buyer.html                         只想改收购机？只放这一个文件就行
        ├── factory_terminal.html
        └── resources/1.ico                    你自己的图片
```

### 三条路径规则（缺一不可）

| 写法 | 解析成 | 用途 |
|---|---|---|
| `/default/a.png`（或 `default/a.png`） | 从 **`theme/` 根**开始找 | **引用默认主题的资源** |
| `./a.png`、`a.png`、`resources/1.ico` | 相对**当前 html 所在目录** | **用你自己的资源** |
| 自己目录里找不到 | 自动去 **`theme/default/`** 找同名文件 | 所以"只改配色"不用复制那十个 html |

```html
<!-- 三种都合法，随便混用 -->
<link rel="stylesheet" href="theme.css">                 <!-- 你自己目录里的（没有就用 default 的） -->
<div style="background-image: url(/default/panel.png)"></div>   <!-- 默认主题的图 -->
<img src="resources/1.ico">                              <!-- 你自己的图标 -->
```

> ⚠️ **安全**：`../` 想跑出 `theme/` 的一律拒绝；`http://`、`data:` 一律拒绝。
> 主题**不能联网**，也读不到游戏目录以外的文件（玩家放一个写坏的主题，模组不会去读别的文件）。

### ★ 共用底层：`base.css`（写主题最省事的办法）

默认主题拆成了**两层**，这样你不用复制几百行没改过的 CSS：

| 文件 | 放什么 | 约定 |
|---|---|---|
| **`base.css`** | **共用底层**：配色、字号、标题条、按钮、列表、信息栏、定位工具 | ★ **类名和结构不会删**（只会加/调数值）→ 引用它是安全的 |
| `theme.css` | 机器界面补充：原生槽位占位（`.slotgrid`/`.slot`/`.player`）+ 主题选择菜单 | 可以跟着界面走 |

自己写主题时直接引用模组自带的那份底层：

```html
<!-- 你自己目录里的 buyer.html -->
<link rel="stylesheet" href="/default/base.css">     <!-- ① 模组自带的共用底层 -->
<link rel="stylesheet" href="/default/theme.css">    <!-- ② 机器界面补充（槽位占位） -->
<link rel="stylesheet" href="我的覆盖.css">            <!-- ③ 只写你要改的 -->
```

好处：
- 只写十几行覆盖，而不是复制 300 行；
- **模组更新默认主题时你会一起拿到新样式**（比如列表高度调过了，你不用手动同步）；
- 各界面仍然**各自一个 html**，互不影响 —— 你只动 `buyer.html` 就只影响收购投送机。

> 想彻底独立（不再跟随默认主题）：把 `base.css` 复制到你自己目录里，然后
> `<link href="base.css">`（相对路径优先于 `/default/`），之后就完全归你管了。

### 能跑的最小例子（仓库里现成的）

`examples/theme-示例-只改收购机/` —— **只有一个 `buyer.html`**，演示"一个界面独立、其余共用默认"：

```
examples/theme-示例-只改收购机/
├── index.json      ← 主题元数据（主题菜单里显示的名称/作者）
└── buyer.html      ← 只覆盖收购投送机这一个界面
```

它里面就三段样式：`html,body` 换底色、`.bar` 换标题条、`.btn` 换按钮颜色 ——
其余全部来自 `/default/base.css`。**九个没提到的界面自动用模组默认主题**
（校验时它们报"没有这个文件"，那是**正常的**，不是错误）。

看效果（不用进游戏）：

```powershell
gradlew checkThemes  -Ptheme="examples/theme-示例-只改收购机"
gradlew renderThemes -Ptheme="examples/theme-示例-只改收购机"
# → build/theme-preview/buyer.png（只有这一个界面会出图，其余没有文件）

# 想用到游戏里：把那个文件夹整个复制到
#   <版本文件夹>/deepspacedeployer/theme/custom/示例-只改收购机/
# 然后按 E 打开背包 → 点左上角那颗圆形「主题」按钮 → 选它
```

> `-Ptheme=` 也可以指向游戏目录里的主题（绝对路径即可），
> 所以"改完先看效果、再进游戏"这条流程在自己电脑上也一样用。

### 缺文件会怎样

`custom/AUI/` 里没有 `market.html` → **自动用 `default/market.html` 的排版**，
但样式和图片**仍然优先从 `AUI/` 找**。所以：

- 只改配色 → 放一个 `theme.css`；
- 只改一个界面 → 放那一个 `.html`；
- 全都要改 → 把 `default/` 整份复制过来。

## 二、五个界面文件长什么样（新版 vs 老板最初的说法）

老板最初的说法是"一个 html 一个界面"，落地时按**"玩家实际看到的界面"**来拆，
所以机器界面从 1 个拆成了 4 个（四个方块的界面内容完全不同）：

| 界面（玩家看到的） | 文件 | 怎么打开 |
|---|---|---|
| 工厂终端（商店） | `factory_terminal.html` | 右键工厂终端 |
| 收购投送机 | `buyer.html` | 右键收购投送机 |
| 载具打印机 | `factory_core.html` | 右键载具打印机 |
| 寄售市场 | `market.html` | 右键寄售市场 |
| 资金转化 | `transfer.html` | 上面四个界面里的「资金转化」按钮 |
| 投放点选择 | `assembly_map.html` | 载具打印机里点「投放点」 |
| 银行卡绑定 | `card_bind.html` | 手持银行卡右键 |
| 通用终端 | `universal_terminal.html` | 右键通用终端 |
| 价目表编辑器 | `shop_editor.html` | ESC 菜单 →「价目表编辑器」（OP） |
| 主题选择菜单 | **原生实现**（不再读 `choice.html`） | 背包界面（E）里的圆形「主题」按钮 |

> `index.html` 保留为**引导页/备用入口**（老版本单文件方案的入口），新主题不用管它。

**每个界面一张"版面预算"表**（画布尺寸是固定的，写超了会溢出）：

| 文件 | 画布 | 可用高度 | 说明 |
|---|---|---|---|
| `factory_terminal.html` | 288×300 | **216** | y=216 以下是原版画的玩家背包（固定） |
| `buyer.html` | 288×300 | 216 | 同上 |
| `factory_core.html` | 288×300 | 216 | 同上 |
| `market.html` | 288×300 | 216 | 同上 |
| `transfer.html` | 288×300 | 216 | 同上 |
| `universal_terminal.html` | 268×270 | 186 | 同上 |
| `assembly_map.html` | 320×300 | 300 | 没有物品格 |
| `card_bind.html` | 260×300 | 300 | 没有物品格 |
| `shop_editor.html` | 340×340 | 340 | 没有物品格 |
| `choice.html` | 260×270 | 270 | 没有物品格 |

> 玩家背包那 76px 是**原版画的**（3×9 + 快捷栏），位置固定在窗口底部 ——
> 所以主题里用 `class="player absolute"` 标记它（`bottom:8`），**别用顺序排**
> （顺序排会把它推到窗口外面去，而且会把前面的内容挤到它身上）。
>
> **怎么知道自己写超了**：`gradlew checkThemes` 会报 `⚠溢出` 并给出实际内容高度 ——
> 这是唯一权威的判断方式，不要靠眼睛估。

## 三、支持的写法（这就是能力边界）

超出的写法**静默忽略** —— 不报错、不崩。抄网上的 CSS 进来，最差只是那几条不生效。

### 标签

`div` `span` `b` `i` `p` `img` `br` `hr`

- `span`/`b`/`i`/`br` 是**行内**（参与文字折行）；
- `img` 当**块级**处理（不支持行内图文混排）；
- `<script>` 在解析阶段就**整段丢弃**（主题不能执行任何东西）；
- `<style>` 块和 `<link rel="stylesheet">` 都支持。

### 选择器

`tag`、`.class`、`#id`、后代组合（`.a .b`）、逗号分组（`.a, .b`）。
层叠顺序：内联 `style=""` > 具体度高的 > 靠后的；具体度 = `id×100 + class×10 + tag`。

**不支持**：`>`、`+`、`~`、伪类（`:hover`）、属性选择器 `[x=y]`。

### 属性

| 类别 | 属性 |
|---|---|
| 颜色 | `color` `background` `background-color` `border-color`（`#RGB` `#RRGGBB` `#AARRGGBB` `rgb()` `rgba()` 少量色名）|
| 图片 | `background-image: url(a.png)`、`background-size: stretch`、`image-rendering: pixelated` |
| 盒子 | `width` `height`（px / %）、`padding` `margin`（1~4 值简写）、`border` `border-width` `border-radius` |
| 文字 | `font-size` `text-align`（left/center/right）、`line-height` |
| 布局 | `display`（block / flex / none）、`flex-direction`（row/column）、`align-items`、`justify-content`、`gap` |
| 定位 | `position`（static/relative/absolute）、`top` `right` `bottom` `left` |
| 其它 | `opacity`、`overflow`（visible/hidden/scroll）|

### ⚠️ 三条和浏览器不一样的地方（踩过坑，记住）

1. **`width`/`height` 是"含 padding 与 border 的边框盒"**（CSS 里的 border-box），
   不是浏览器默认的 content-box —— 所以 `width:100%` 加 padding **不会**溢出；
2. **写了 `height` 的容器，内容再多也只占那么高**（多出来的被 `overflow` 裁掉，不会把后面的元素推下去）；
3. **`position:absolute` 的元素不占文档流**（这就是玩家背包要用绝对定位的原因）。

### 不支持（v1）

JS、动画/过渡、`flex-wrap`、`grid`、渐变、阴影、自定义字体文件、外链网络资源、
行内图文混排、`float`、外边距合并、表格、媒体查询。

## 四、数据绑定（没有 JS，靠这三样半）

| 写法 | 作用 |
|---|---|
| `{{键名}}` | 换成真实数据（**在折行之前**替换，所以宽度算得准）；**属性里也能用**（见下） |
| `data-if="键名"` / `data-if="!键名"` | 条件为假时这个元素**完全不参与布局**（等价 `display:none`）|
| `data-repeat="列表"` | 按 `列表.count` 把这段元素复制 N 份 |
| `data-action="动作名"` | 点击时把动作名发给模组（按钮就这么做）|
| `{{行号}}` | **只在 `data-repeat` 里面可用**：当前是第几行（从 0 数）|

### 列表：`data-repeat` 怎么用

数据侧会长成这样（模组自动填的）：

```
商品.count = 3            ← 有几项
商品.0.名称 = 铁锭          ← 第 0 项的字段
商品.0.单价 = 8
商品.1.名称 = 铜锭
…
```

主题里这么写：

```html
<div class="row" data-repeat="商品">
  <div class="name">{{名称}}</div>     <!-- 自动解析成 商品.0.名称 -->
  <div class="price">{{单价}}</div>
  <div class="btn" data-action="buy" data-index="{{行号}}">买</div>
</div>
<div class="empty" data-if="!商品数量">没有商品</div>   <!-- 列表为空时才显示 -->
```

- 行里写 `{{名称}}` 会**先找 `商品.0.名称`，找不到再找全局的 `名称`** ——
  所以行里也能引用全局数据（比如每行都显示一次 `{{余额}}`）；
- **`{{行号}}`** 只在 `data-repeat` 里可用：当前是第几行（从 0 数）——
  列表里的按钮靠它知道"点的是第几条"；
- **属性里的 `{{...}}` 也会替换**（所以 `data-index="{{行号}}"` 能生效）；
- 列表**条数**有两种写法：`{{商品数量}}` 或 `{{商品.count}}`（绑定器会自动映射，
  见 [界面清单.md](界面清单.md) 的"列表计数怎么写"）；
- **`data-action` 本身要写死的动作名**，不要把动作名做成占位符（日志里看不出点了什么）。

### 点击怎么变成动作

点到一个元素后，渲染器会**往上找最近的带 `data-action` 的祖先** ——
所以你可以把 `data-action` 写在容器上，里面放图标/文字/多个 div，点哪都算点到按钮。

动作名带参数用冒号：`use:我的主题`、`buy:5`。具体每个界面支持哪些动作，
见默认主题里那个 html 的注释头（`theme/default/*.html` 开头都写了）。

## 五、不用开游戏就能验证（★ 最实用的一节）

主题改完**先出图看一眼**，确认没问题再进游戏 —— 用的是**和游戏内同一段布局 + 绘制代码**，
差别只有"字形由系统字体画"（位置是准的，笔画细节不同）。

```powershell
# ① 校验：十个界面一个个加载（解析 / 绑定 / 布局），报告元素数、动作、有没有溢出
gradlew checkThemes

# ② 出图：每个界面渲染成 PNG，出到 build\theme-preview\
gradlew renderThemes

# ③ 排版分解：某个界面"内容高得离谱"时，打印每个元素的 y 和高度
gradlew dumpTheme -Pfile=buyer.html
```

`checkThemes` 的输出长这样（**⚠溢出** 就是内容超出了版面预算，要去压一压）：

```
=== 界面主题校验（10 个界面）===
  ✓ buyer.html                元素 42 规则 49 内容高 270/270
      动作 [toggle_autosell, sell_now, open_transfer]
      占位 [card, input9, player]
  ✓ factory_core.html         元素 44 规则 49 内容高 274/270 ⚠溢出
…
```

> 这套工具**不需要启动游戏**，因为主题内核（`ui/theme` 包）里除了 `ThemeManager`
> 一个 NeoForge 类都不引用 —— 这是当初刻意设计的，为了"改一行 CSS 就能马上看到结果"。

## 六、新增一套主题（手把手）

### 先认识那颗圆形按钮（主题入口）

按 **E** 打开背包，**屏幕底部居中**会有一颗圆形的「**主题**」按钮
（默认**不在左上角** —— 那里常被 FTB 这类模组的按钮占住，被盖住就完全看不见了）：

| 操作 | 效果 |
|---|---|
| **左键点击** | 打开主题选择界面（原生界面，见下面的「资源包式」说明） |
| **右键长按拖拽** | 慢慢挪位置；**松手即记住** |
| **按「移动界面主题按钮」键**（默认**鼠标中键**） | 在背包界面里把鼠标移到想去的地方按一下 → 按钮**搬过去**（也记住） |

键位在 **选项 → 控制 → 按键绑定 →「深空铸造体」** 里改，键盘键、鼠标键都能录
（见 `ThemeKeys.MOVE_BUTTON`）。

位置记在 `config/deepspacedeployer-common.toml` 的 `ui.theme_button_x/y`；
初始值是 `-1` = "按屏幕尺寸自动放底部居中"。
换分辨率 / 改界面缩放后会被自动拉回可视范围，不会跑到屏幕外"消失"。

> 中键**只在没悬停在有物品的格子上时才搬按钮** —— 创造模式里"中键复制物品"照旧能用
> （见 `ClientSetup.wouldCloneItem`）。默认动作不吞事件，交互和原版一致。
> 按钮**可以盖在物品栏上** —— 原版没有这种限制，槽位照样能点
> （按钮只占 20×20，且最后加入渲染，点按钮不会穿透到槽位）。
>

`index.json` 可以写主题信息，**主题选择界面**会显示出来（图标 / 名称 / 版本 / 作者 / 介绍）：

```json
{
  "name": "我的主题",
  "author": "老板",
  "version": "1.0",
  "description": "一句话介绍",
  "icon": "icon.png"
}
```

| 字段 | 作用 | 缺了会怎样 |
|---|---|---|
| `name` | 显示名 | 用文件夹名 |
| `author` | 作者 | 显示"未知作者" |
| `version` | 版本（显示成 `v1.0`） | 不显示 |
| `description` | 一句话介绍（一行、超长自动截断） | 不显示 |
| **`icon`** | **图标**：相对**主题文件夹**的路径，和 `index.json` 同级 | 默认找 `icon.png`；再找不到就用 `default` 主题的图标 |

> ⚠️ `icon` 只用**相对路径**（`icon.png`、`art/logo.png`），不要写绝对路径、不要写 `http://`。
> 建议放一张 128×128 或 64×64 的 PNG（界面里按 32×32 显示）。

**主题名不存在 / 文件写坏 → 安静回退 `default`**，不会报错、不会崩。

### 主题选择界面怎么用（资源包式）

按 **E** → 点那颗圆形「主题」按钮：

- **左右两栏**：左 = 可用（未启用），右 = 已启用；
- **点左边 → 启用**（移到右边），**点右边 → 禁用**（移回去），可以同时启用多套；
- 启用列表里**最后一个**负责渲染没有单独指定的界面（和资源包的"下面的覆盖上面的"一个意思）；
- **「高级界面设置…」**：给每个界面单独指定主题（10 个界面两列列出，点一下循环切换）；
  - 点「应用」后，被指定到的主题会自动启用；
  - 这时界面上会出现黄字提示：**正在使用自定义配置，启用其他主题会清空当前配置**；
  - 真的启用了别的主题 → 高级配置被清空，所有界面归新主题渲染；
  - 禁用了某套主题 → 它负责的界面**回落到 `default`**。

对应配置：`ui.theme_list`（启用列表，逗号分隔）、`ui.theme_assign`（高级指定，`界面=主题;…`）。

> 主题选择界面本身是**原生实现**（需要滚动列表 / 多选 / 循环切换，HTML 子集做不可靠）。
> `choice.html` 仍留在默认主题里，可以用 `gradlew renderThemes` 预览，但游戏内不再加载它。

## 七、原生控件占位（物品格、输入框）

物品格和输入框**必须由原版画**（要支持拖拽、右键分堆、shift 移动、光标输入），
主题只负责**标记它们摆在哪**：

```html
<div data-slot="card"     class="slot"></div>      <!-- 银行卡槽（1 格，18×18）-->
<div data-slot="input9"   class="slots9"></div>    <!-- 3×3 投料格（54×54）-->
<div data-slot="player"   class="player absolute"></div>  <!-- 玩家背包 3×9 + 快捷栏（162×76）-->
<div data-input="价格"    class="btn ghost"></div>  <!-- 原版输入框摆这里 -->
```

| 标记 | 内容 | 出现在哪几个界面 |
|---|---|---|
| `slot:card` | 银行卡槽（1 格） | 商店 / 收购机 / 打印机 / 市场 / 资金转化 / 通用终端 |
| `slot:input9` | 3×3 投料格 | 收购机 / 打印机 |
| `slot:clipboard` | 机械动力剪贴板格 | 打印机 |
| `slot:market_sell` / `market_barter` / `market_collect` | 市场三格 | 市场 |
| `slot:card6` | 6 个公司卡槽（3×2） | 通用终端 |
| `slot:player` | 玩家背包 + 快捷栏 | 上面六个机器界面 |
| `input:金额` / `input:目标` | 金额框 / 对方玩家名框 | 资金转化 |
| `input:玩家名` / `input:卡名` | 绑定界面两个输入框 | 银行卡绑定 |
| `input:价格` | 价目表价格框 | 价目表编辑器 |
| `map:俯视图` | 俯视图贴图（运行时生成） | 投放点选择 |

**尺寸要按 18 的整数倍给**（原版格子 18×18），否则格子和面板会错位。
主题里这些容器的宽高会**决定原版控件的位置**（Java 侧按布局算出来的坐标摆）。

## 八、常见问题（FAQ）

**Q：改了文件没生效？**
A：主题是**打开界面时**读的，关掉界面重开即可（不用重启游戏）。
换主题名要重新打开界面；`/dsd selftest` 里也有一段主题自检。

**Q：界面变回老样子了（原生界面）？**
A：说明这个界面的 html 加载失败了 —— 这是**故意设计**的兜底：主题写坏最差就是"变回老样子"，
绝不会打不开。去日志里搜 `[深空铸造体][界面]` 看原因。

**Q：想彻底关掉主题？**
A：`config/deepspacedeployer-common.toml` 里 `ui.theme_enabled = false`，所有界面都用原生界面。

**Q：字体能换吗？**
A：不能（v1）。文字用游戏自带字体渲染，好处是中文字宽和游戏一致、换行位置准。

**Q：能做动画吗？**
A：不能。要"动起来"只能靠不同状态换布局（比如 `data-if` 切换两套 div）。

**Q：为什么 `:hover` 不生效？**
A：不支持伪类。鼠标悬停的高亮做不了（v1）。

**Q：`padding: 0 6` 这种简写支持吗？**
A：支持，和浏览器一样（上下 0、左右 6）。

## 九、代码地图（要改渲染器时看这里）

| 文件 | 职责 |
|---|---|
| `ui/webview/WebViewScreen` | **宿主**：加载主题、每帧绘制、把点击翻成动作、失败回退原生界面 |
| `ui/webview/WebViewManager` | 客户端总开关：释放默认主题、读配置、每 tick 检查主题有没有被换掉 |
| `ui/webview/ThemeChoiceScreen` | 主题选择界面：左右两栏（可用/已启用）+ 高级界面设置（**原生实现**） |
| `ui/webview/ThemeContext` | 一份"加载好的文档 + 布局结果"：命中测试、槽位标记、诊断 |
| `ui/webview/GuiCanvas` | **游戏内画布**（`GuiGraphics` 实现）+ 贴图缓存 + 只量不画的版本 |
| `ui/webview/ThemeData` | 喂给主题的数据（扁平键值表 + 列表） |
| `ui/webview/WebScreenId` | **界面登记表**：每个界面对应哪个 html、多大 |
| `ui/theme/ThemeSource` | 路径解析 + 回退链 + 越界拦截（三条路径规则在这里） |
| `ui/theme/ThemeDocument` | 加载入口：HTML → CSS → **绑定数据 → 解析样式**（顺序不能反！） |
| `ui/theme/HtmlParser` / `CssParser` | 解析；**属性清单就是 `CssParser.apply` 里的 switch**（想加属性从这里加） |
| `ui/theme/LayoutEngine` | 树 + 样式 → 每个元素的位置（块级 / flex / 文字折行 / absolute） |
| `ui/theme/ThemeRenderer` + `Canvas` | 布局 → 画面；**游戏内与离线预览共用这一段** |
| `ui/theme/PreviewCanvas` | Java2D 实现（离线出图 / 回归用） |
| `tools/ThemePreview` | `checkThemes` / `renderThemes` / `dumpTheme` 三个任务背后的工具 |

### 三条硬规矩（都踩过，别重复）

1. **先绑定数据、再解析样式** —— `data-repeat` 会克隆节点，顺序反了新节点没有样式 → 布局空指针；
2. **`ui/theme` 包不许引用 `ThemeManager`/NeoForge** —— 一旦引用，离线预览就编译不过
   （便利方法请加在 `ThemeManager` 上，或者在 `ui/webview` 包里写）；
3. **游戏内和离线必须用同一套字宽度量** —— 两边换行位置不一致，就成了"预览里一行、游戏里两行"。
   所以布局用的画布要么是真的 `GuiCanvas`，要么是 `GuiCanvas.measureOnly()`。

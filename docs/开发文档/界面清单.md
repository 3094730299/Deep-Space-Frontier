# 深空铸造体 · 界面清单（要渲染哪些 UI / 各自对应哪个 html）

> **这份文档回答一个问题：模组里到底有几个地方需要画界面，每个界面对应主题目录里的哪个文件。**
>
> 规则（老板定稿）：**一个界面 = 一个 `.html` 文件**（CSS 可以外挂一个同名 `.css`，也可以内嵌 `<style>`）。
> 主题目录约定与资源引用规则见 [界面主题系统.md](界面主题系统.md)。
>
> 最后更新：2026-10-16 · 对应模组 **0.1.1+mc1.21.1**

## 二、文件名怎么定（规则）

```
<版本文件夹>/deepspacedeployer/theme/
├── default/                        ← 模组内置（首次启动释放；更新时会被覆盖）
│   ├── factory_terminal.html
│   ├── buyer.html
│   ├── factory_core.html
│   ├── market.html
│   ├── transfer.html
│   ├── assembly_map.html
│   ├── card_bind.html
│   ├── universal_terminal.html
│   ├── shop_editor.html
│   ├── choice.html
│   ├── theme.css                   ← 公共样式（每个 html 都能 <link> 它）
│   └── version.txt
└── custom/
    └── AUI/                        ← 一套自定义主题 = 一个文件夹
        ├── index.json              ← 元数据：名称/作者/版本/介绍（可选）
        ├── buyer.html              ← 只改收购投送机？只放这一个文件就行
        ├── theme.css
        └── resources/1.ico
```

**三条硬规则**：

1. **缺文件就回退**：`custom/AUI/` 里没有 `buyer.html` → 自动用 `default/buyer.html` 的排版，
   但**样式和资源仍优先从 `AUI/` 找**（所以只想改一套配色，只需放一个 `theme.css`）；
2. **图片引用两种写法都行**（见 [界面主题系统.md](界面主题系统.md) 第二节）：
   - `default/a.png` 或 `/default/a.png` → 从 `theme/` 根开始找（**用默认主题的资源**）；
   - `./a.png`、`a.png`、`resources/1.ico` → 相对**当前 html 所在目录**（**用自己的资源**）；
   - 自己的目录里找不到 → **自动去 `default/` 找同名文件**；
3. **`index.html` 不再是唯一入口**（旧的单文件方案作废）——
   现在按上表的文件名逐个加载；`index.html` 保留为"引导页/备用入口"。

### ★ 版面预算（写主题必须看，超了会压到背包上被裁）

| 文件 | 画布（宽×高） | 可用高度 | 说明 |
|---|---|---|---|
| `factory_terminal.html` | 288×300 | **216** | y=216 以下是原版画的玩家背包（固定） |
| `buyer.html` | 288×300 | 216 | 同上 |
| `factory_core.html` | 288×300 | 216 | 同上 |
| `market.html` | 288×300 | 216 | 同上 |
| `transfer.html` | 288×300 | 216 | 同上 |
| `universal_terminal.html` | 268×270 | 186 | 同上 |
| `assembly_map.html` | 320×300 | 300 | 没有物品格 |
| `card_bind.html` | 260×300 | 300 | 没有物品格 |
| `shop_editor.html` | 340×340 | 340 | 没有物品格 |
| `choice.html` | 260×270 | 270 | 没有物品格 |

> **为什么机器界面是 300 高**：一个窗口要同时装"原版背包（占最下面 76px）"和"主题画的上半部分"。
> 270 高时上面只剩 186px，`标题条 + 信息栏 + 槽位行 + 按钮行 + 列表` 塞不下
> （会压到背包上、最后一行被裁）。2026-10-16 把 `MachineScreen.imageHeight` 加到 300，上面就有 216px。
> 主题里的 `.player` 用 `bottom:8` 定位，所以**改窗口高度不用同步改主题**。
> 尺寸登记在 `ui/webview/WebScreenId`（改那里要同步改本表），
> 唯一权威的验证方式是 `gradlew checkThemes`（报"⚠溢出"就是超了）。

### 列表计数怎么写（`data-if="!商品数量"`）

列表的条数存在 `商品.count` 里。`data-if` 只认单个键名、不会拼字符串，所以
`DataBinder` 会自动把 `X.count` 也映射成 **`X数量`**（扫到 `data-repeat="X"` 就自动生成）。
两种写法都能用：

```html
<div class="empty" data-if="!商品数量">没有商品</div>   <!-- 推荐：短 -->
<div class="empty" data-if="!商品.count">没有商品</div> <!-- 也行 -->
```

> ⚠️ 这个映射是 2026-10-16 补的：在那之前 `data-if="!商品数量"` **永远取不到值**
> → 空状态提示在列表有内容时也照样显示，把后面的行往下顶、最后一行被背包盖住。
> 现在这类条件由绑定器统一兜住，Java 侧<b>不需要</b>再额外 put 一个 `X数量`。

## 三、每个界面要绑的数据与动作

> 写法：`{{键名}}`、`data-if="键名"`、`data-repeat="列表"`、`data-action="动作名"`。
> **没有 JS** —— 动起来全靠这四样（详见 [界面主题系统.md](界面主题系统.md) 第四节）。
>
> ⚠️ 下表是**设计契约**：Java 侧要按这些键名往界面喂数据，主题作者照这些键名写。
> 标 ✅ 的是**已经能从现有代码里取到**的数据（方块实体 / 菜单数据槽 / 客户端缓存），
> 标 🔧 的是**接入时要新加**的取数逻辑。

### 1. `factory_terminal.html` —— 工厂终端（商店）

| 类别 | 键 / 动作 | 说明 |
|---|---|---|
| 数据 | `公司` `账户` `余额` `卡余额` `等级` `声望` `在线` | ✅ 取自菜单数据槽 / 银行卡 |
| 数据 | `页` `总页` `商品[]` | 🔧 商品列表来自 `ClientShopCache` |
| 列表项 | `名称` `单价` `等级需求` `声望需求` `可买` | 每项一条，`可买=0` 时该行置灰 |
| 动作 | `buy:<下标>` `page_prev` `page_next` `open_transfer` | 对应 `ACTION_BUY_BASE + i` / 200 / 201 / 202 |

## 四、原生槽位（物品格）怎么处理

界面上有**原版物品格**（背包、卡槽、投料格 3×3、市场三格、剪贴板格），
这些格子由原版渲染（要支持拖拽/右键分堆/shift 移动），**不能**用 HTML 画。

做法：主题里用标记占位，Java 侧把原版槽位画在标记的位置上：

```html
<!-- 收购投送机：3×3 投料格 + 左侧卡槽 -->
<div class="slots" data-slot="input9"></div>   <!-- 9 个投料格 -->
<div class="slot"  data-slot="card"></div>     <!-- 银行卡槽 -->
<div class="inv"   data-slot="player"></div>   <!-- 玩家背包 3×9 + 快捷栏 -->
```

| 标记 | 内容 | 出现在 |
|---|---|---|
| `card` | 银行卡槽（1 格） | 1~4、8 |
| `input9` | 3×3 投料格 | 2、3 |
| `clipboard` | 机械动力剪贴板格 | 3 |
| `market_sell` / `market_barter` / `market_collect` | 市场三格 | 4 |
| `card6` | 6 个公司卡槽 | 8 |
| `player` | 玩家背包 + 快捷栏 | 1~5、8 |
| `map` | 俯视图贴图（运行时生成） | 6 |

> **槽位尺寸固定 18×18**（原版），所以主题里这些容器的宽高最好是 18 的整数倍，
> 否则格子会和面板对不齐。Java 侧**按数据槽里的坐标反推**：标记元素在布局里的绝对位置 = 槽位左上角。

## 五、还没定 / 已知限制

| 项 | 现状 |
|---|---|
| 文本输入框（金额、搜索、玩家名、价格） | 原版 `EditBox` **不能**画进 HTML。v1 做法：主题标记位置（`data-input="价格"`），Java 侧把原版输入框摆上去；主题无法控制它的字体和光标样式 |
| 滚动 | 主题里 `overflow: scroll` 由渲染器自己实现滚动条（滚轮生效），**不与原版控件共用** |
| 悬停提示（物品 tooltip） | 主题画的物品名**没有**原版 tooltip；需要 tooltip 的地方用原生槽位（鼠标悬停原版会自己画） |
| 动画/过渡 | 不支持。要"动起来"只能靠不同状态换布局 |
| 汉字的字形 | 用原版字体渲染时字宽和游戏一致（半角 6px / 全角 9px），**位置可信、字形由游戏字体决定** |

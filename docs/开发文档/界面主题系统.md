# 深空铸造体 · 界面主题系统（HTML + CSS）

> **这份文档面向要改界面的人（包括 AI）**。看完你应该能：新建一套主题、改样式、
> 用离线预览出图、知道哪些写法支持、哪些不支持。

最后更新：2026-10-15 · 对应模组 0.1.0+mc1.21.1

---

## 一、这是什么

模组的机器界面（商店 / 收购投送机 / 载具打印机 / 寄售市场 / 资金转化）可以由
**HTML + CSS** 描述，放在游戏目录里，玩家随时替换。

**三个已经定死的设计选择**（都是老板拍板的，不要擅自改）：

| 选择 | 原因 |
|---|---|
| **不用 Chromium / WebView**，自己写 HTML/CSS 子集渲染器 | 真浏览器内核是每平台上百 MB 的原生库，且要联网下载；老板要的是"**内置**、玩家零安装"。自写渲染器还带来一个关键好处：**能离线出预览图** |
| **不允许 JS** | 主题只能"描述长什么样"，不能执行任何东西。动起来靠占位符 + `data-if` + `data-repeat` |
| **渲染失败自动回退原生界面** | 主题写坏了最差是"界面变回老样子"，绝不会打不开 |

## 二、目录与资源解析

```
<版本文件夹>/                       ← 例如 .minecraft/versions/孢子危机/
└── deepspacedeployer/
    └── theme/
        ├── default/              ← 模组内置的默认主题（首次启动释放到磁盘）
        │   ├── version.txt       ← 版本标记：和 jar 里不一致就整份重写
        │   ├── index.html        ← 机器界面入口
        │   ├── choice.html       ← 主题选择菜单（每套主题自带）
        │   ├── theme.css
        │   └── *.png
        └── custom/
            └── 我的主题/          ← 一套自定义主题 = 一个文件夹
                ├── index.html     ← 必须叫这个名字
                ├── *.css
                ├── *.png
                └── resources/1.ico
```

**三条路径规则**（`ThemeSource`）：

1. **`/` 开头** → 相对 `theme/` 根。例：`/default/a.png` = `theme/default/a.png`；
2. **其他** → 相对**引用它的那个文件所在目录**。例：`./a.png`、`a.png`、`resources/1.ico`；
3. **找不到就回退**：自定义主题里缺的资源，自动去 `theme/default/` 找同名文件。

> ⚠️ `../` 想跑出 `theme/` 的一律拒绝；`http://`、`data:` 一律拒绝 —— 主题**不能联网**。

**`default/` 会被覆盖，`custom/` 永远不会。** 想长期保留就把 `default/` 复制到 `custom/` 里改。

## 三、支持的写法（这就是能力边界）

超出的写法**静默忽略**，不会报错、不会崩 —— 抄网上的 CSS 进来最差只是那几条不生效。

### 标签

`div` `span` `b` `i` `p` `img` `br` `hr`

> `span`/`b`/`i`/`br` 是**行内**（参与文字折行）；`img` 当**块级**处理（v1 不支持行内图文混排）。
> `<script>` 在解析阶段就整段丢弃。

### 选择器

`tag`、`.class`、`#id`、后代组合（`.a .b`）、逗号分组（`.a, .b`）。
层叠顺序：**内联 `style=""` > 具体度高的 > 靠后的**；具体度 = `id×100 + class×10 + tag`。

不支持：`>`、`+`、`~`、伪类（`:hover`）、属性选择器 `[x=y]`。

### 属性

| 类别 | 属性 |
|---|---|
| 颜色 | `color` `background` `background-color` `border-color`（`#RGB` `#RRGGBB` `#AARRGGBB` `rgb()` `rgba()` 少量色名）|
| 图片 | `background-image: url(a.png)`、`background-size: stretch`、`image-rendering: pixelated` |
| 盒子 | `width` `height`（px / %）、`padding` `margin`（1~4 值简写）、`border` `border-width` `border-radius` |
| 文字 | `font-size` `text-align`（left/center/right）、`line-height` |
| 布局 | `display`（block / flex / none）、`flex-direction`（row/column）、`align-items`、`justify-content`（flex-start/center/flex-end/space-between）、`gap` |
| 定位 | `position`（static/relative/absolute）、`top` `right` `bottom` `left` |
| 其它 | `opacity`、`overflow`（visible/hidden/scroll）|

### ⚠️ 一个和浏览器不同的地方

**`width`/`height` 是"含 padding 与 border 的边框盒"**（CSS 里叫 border-box），
不是浏览器默认的 content-box。也就是说：

```css
.box { width: 100%; padding: 6; }   /* 不会溢出，总宽就是容器的 100% */
```

写游戏界面这样更不容易踩坑，但抄网上的 CSS 时要记得这一条。

### 不支持（v1）

JS、动画/过渡、`flex-wrap`、`grid`、渐变、阴影、自定义字体文件、外链网络资源、
行内图文混排、`float`、外边距合并、表格。

## 四、数据绑定（没有 JS，靠这三样）

| 写法 | 作用 |
|---|---|
| `{{键名}}` | 换成真实数据（**在折行之前**替换，所以宽度算得准）|
| `data-if="键名"` / `data-if="!键名"` | 条件为假时这个元素**完全不参与布局**（等价 `display:none`）|
| `data-repeat="列表"` | 按 `列表.count` 把这段元素复制 N 份 |
| `data-action="动作名"` | 点击时把动作名发给模组（按钮就这么做）|

**列表里怎么取每项的值**：`data-repeat="items"` 里面的 `{{名称}}` 会自动解析成
`items.0.名称`、`items.1.名称`……同时**全局键仍然可用**（比如行里也能写 `{{余额}}`）。

真假规则：`null`、空串、`0`、`false`、`no`、`off` 都算假。

## 五、离线预览（改主题不用开游戏）

主题核心包**除 `ThemeManager` 外不引用任何 MC/NeoForge 类**，所以能用纯 javac 直接跑出 PNG：

```powershell
# 1) 只编译主题核心（不含 ThemeManager）
$names = 'ThemeSource','Dim','Style','LayoutBox','HtmlNode','HtmlParser','CssParser',
         'StyleResolver','ThemeDocument','Canvas','LayoutEngine','DataBinder',
         'ThemeRenderer','PreviewCanvas'
javac -encoding UTF-8 -d out ($names | % { "src\main\java\com\deepspacedeployer\ui\theme\$_.java" })

# 2) 渲染一张图（@文件 = UTF-8 的 key=value 假数据，避免中文走命令行被编码坑）
java -cp out com.deepspacedeployer.ui.theme.PreviewCanvas `
     src\main\resources\assets\deepspacedeployer\theme\default 256 200 preview.png "@demo-data.txt"
```

> 预览用**原版字宽规则**排版（半角 6px / 全角 9px，字号 9），所以**换行位置和游戏里一致**；
> 笔画是系统字体画的，字形细节会有差别。**位置对不上才是 bug，字形不同不是。**

## 六、新增一套主题

```text
1. 把 theme/default/ 整个复制成 theme/custom/我的主题/
2. 改 index.html 和 *.css
3. 在 config/deepspacedeployer-common.toml 里把 ui.theme 改成 "我的主题"
   （或者在主题选择菜单里点 —— 菜单本身也是主题化的，见 choice.html）
4. 游戏里按 F3+T 热重载，不用重启
```

主题名不存在时**安静回退 `default`**，不会报错。

## 七、代码地图（要改渲染器时看这里）

| 文件 | 职责 |
|---|---|
| `ThemeManager` | **唯一**碰 NeoForge 的类：游戏目录、配置项、释放内置主题、列主题 |
| `ThemeSource` | 路径解析 + 回退链 + 越界拦截 |
| `ThemeDocument` | 加载入口：读 HTML → 收集 CSS → **绑定数据 → 解析样式**（顺序不能反！）|
| `HtmlParser` / `HtmlNode` | HTML → 节点树（`<script>` 丢弃）|
| `CssParser` / `Style` | CSS → 规则；属性清单就是 `CssParser.apply` 里的 switch |
| `StyleResolver` | 继承 + 层叠 → 每个元素的最终 `Style` |
| `DataBinder` | 占位符 / `data-if` / `data-repeat` |
| `LayoutEngine` | 树 + 样式 → 每个元素的 `LayoutBox`（绝对坐标）|
| `ThemeRenderer` + `Canvas` | 布局 → 画面；**游戏内与离线预览共用这一段** |
| `PreviewCanvas` | Java2D 实现 + 命令行入口 |
| `GuiCanvas`（待做） | `GuiGraphics` 实现，游戏内用 |

**两条硬规矩**（都踩过）：

1. **先绑定数据、再解析样式** —— `data-repeat` 会克隆节点，克隆发生在解析之后的话，
   新节点没有样式，布局直接空指针；
2. **`ThemeDocument` 不许引用 `ThemeManager`** —— 一旦引用，离线预览就编译不过
   （`ThemeManager` 依赖 NeoForge）。便利方法请加在 `ThemeManager` 上。
